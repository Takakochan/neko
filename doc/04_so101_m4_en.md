# Running the SO-101 on an M4 Mac (Apple Silicon)

[日本語](04_so101_m4.md)

LeRobot works on Apple Silicon Macs (M1–M4), so on these machines you prepare the arm (find the port, calibrate) with the official LeRobot commands and drive `arm_api` through LeRobot as well.

> LeRobot can't be installed on Intel Macs (their PyTorch is too old). On an Intel Mac, use the `so101` backend, which doesn't need LeRobot (see the end of this page).
> The `so101` backend also works on an M4 Mac, so it doubles as a fallback if LeRobot gives you trouble.

Time needed: 30–45 min the first time (mostly installation)

---

## 1. Setup (first time only)

### Install uv (if you don't have it)

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Reopen the terminal, then check with `uv --version`.

### Get the repository

```bash
git clone git@github.com:Takakochan/neko.git
cd neko
```

If you already have it: `cd neko && git pull`.

### Create the venv and install packages

```bash
uv venv --python 3.12
source .venv/bin/activate
uv pip install -r requirements/lerobot.txt
uv pip install --reinstall opencv-python==5.0.0.93
```

- Line 3 installs `requirements.txt` (shared by vision and arm) together with LeRobot. PyTorch is installed here too, so it takes a few minutes
- **Don't skip line 4.** LeRobot pulls in an OpenCV without display support (`opencv-python-headless`) that overwrites `cv2`; without the reinstall, `record_grid.py` can't show the camera window
- Every time you open a new terminal, run `source .venv/bin/activate` before working (you're set when the prompt starts with `(.venv)`)

Check:

```bash
python --version                                                 # Python 3.12.x
python -c "import lerobot, cv2; print(lerobot.__version__, cv2.__version__)"
```

## 2. Connect the arm

1. Plug in the arm's power adapter (USB alone won't move it)
2. Connect the USB cable to the Mac
3. Find the port:

```bash
lerobot-find-port
```

Unplug and replug the USB cable when prompted; it prints a port name like `/dev/tty.usbmodemXXXX`. Replace `<PORT>` below with it. To avoid typing it every time:

```bash
export ARM_PORT=/dev/tty.usbmodemXXXX
```

---

## 3. Calibration (once per arm)

```bash
lerobot-calibrate --robot.type=so101_follower --robot.port=$ARM_PORT --robot.id=so101_follower
```

- Follow the on-screen instructions: put every joint in the middle of its range and press Enter → move each joint from end to end and press Enter
- The offsets are written into the servos themselves, and the settings file is saved under `~/.cache/huggingface/lerobot/calibration/`
- Keep `--robot.id` the same as `arm_api`'s default (`so101_follower`). If you use a different name, add `ARM_ID=<name>` when running

> If the arm was calibrated on an Intel Mac with `python pc/so101_check.py calib`, run `lerobot-calibrate` once more on the M4. When the servo offsets don't match LeRobot's settings file, LeRobot asks you to recalibrate on connect.

### Check the connection

Confirm the joint angles can be read (the arm doesn't move):

```bash
python -c "
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
r = SO101Follower(SO101FollowerConfig(port='$ARM_PORT', id='so101_follower'))
r.connect(); print(r.get_observation()); r.disconnect()"
```

Move the arm a little by hand and run it again; if the numbers change, it's connected.

---

## 4. Make grid.json (after fixing the camera)

Decide where the camera goes, mark it with tape, and **never move it after that**. If it moves, redo the grid.

```bash
python pc/record_grid.py --backend lerobot --port $ARM_PORT
```

1. The arm goes limp. Support it by hand and bring the teaser tip near one of the guide points (3×3) on screen
2. Press `l` to hold the current pose (press `l` again to go limp)
3. Click the teaser tip in the camera view → the joint angles at that moment are recorded
4. After 9 points, put the arm in its rest pose (folded, where it can't hit the cat) and press `h`
5. Press `s` to save to `data/grid.json` (an existing file is kept as `grid.bak-<date>.json`)

Keys: `u` undo the last point / `q` quit without saving

If the camera window doesn't appear, allow the terminal (or VS Code, if you run it from there) under System Settings → Privacy & Security → Camera.

---

## 5. Run it

```bash
ARM_BACKEND=lerobot python pc/arm_api.py
```

The arm moves to its rest pose, then runs each of the four play modes (bird / mouse / peek / tease) for 3 seconds. The integration loop works the same way: start it with `ARM_BACKEND=lerobot` and `arm_api` goes through LeRobot.

### Safety

- **Emergency stop = unplug the arm's power.** `Ctrl+C` only stops the PC side
- Large moves are sent in steps of at most 15°, so the arm won't jump
- LeRobot goes limp automatically when the program exits (both `arm_api.py` and `record_grid.py`). The arm will drop, so support it by hand before exiting, or make the rest pose one where it rests on something
- Test first with no cat around and no teaser attached

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| Error from `cv2.imshow` / no camera window | OpenCV is the headless build. `uv pip install --reinstall opencv-python==5.0.0.93` |
| `set ARM_PORT` | The LeRobot backend needs the port. `export ARM_PORT=...` or `--port` |
| Asked to calibrate on connect | The servo offsets don't match LeRobot's settings file. Follow the prompt, or run `lerobot-calibrate` |
| `grid.json was recorded with 'so101', not 'lerobot'` | grid.json was made with the other backend. The joint values use a different reference (so101: center = 90°, lerobot: center = 0°), so redo it with `--backend lerobot` |
| `needs a real data/grid.json` | There's no grid.json yet. Make it in step 4 |
| Port can't be opened / busy | Another program (e.g. Python in another terminal) is holding the arm. Quit it and try again |
| `python` isn't 3.12 | You forgot `source .venv/bin/activate` |

## Reference: without LeRobot (works on both Intel and M4 Macs)

```bash
uv pip install -r requirements.txt
python pc/so101_check.py watch       # check the connection
python pc/so101_check.py calib       # calibrate (also writes offsets to the servos)
python pc/record_grid.py             # grid.json (--backend so101 is the default)
ARM_BACKEND=so101 python pc/arm_api.py
```

The port is found automatically (if there are several, pass `--port` / `ARM_PORT`).
